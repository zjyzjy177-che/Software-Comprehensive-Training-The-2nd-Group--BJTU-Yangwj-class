## 二、遇到的技术问题与解决方案

### 问题 1：macOS 上 Matplotlib 动画窗口无法弹出

**现象**：GUI 勾选可视化后点启动，动画窗口完全不出来，无报错。

**原因**：visualizer.py 在 macOS 上强制使用 `MacOSX` 后端（Cocoa 事件循环），与 Tkinter 的 Tk 事件循环冲突，`plt.show()` 在 Tk `after` 回调中无法创建窗口。

**解决**：将 macOS 后端从 `MacOSX` 改为 `TkAgg`，Matplotlib 直接复用 Tkinter 的事件循环。同时在 gui.py 模块顶部增加防御性 `matplotlib.use('TkAgg')`。

### 问题 2：macOS 按钮背景色不生效

**现象**：tk.Button 设置的 bg="#CC0000" 红底在 macOS 上显示为白色/透明。

**原因**：macOS Aqua 主题强制接管原生 Button 控件外观，忽略 bg/fg 参数。

**解决**：编写 `_make_btn` 工具函数，用 Frame + Label 组合模拟按钮。Frame 不是原生 Button，Aqua 不会管，bg/fg 正常生效。项目内所有彩色按钮（管理员入口、验证登录、取消、启动仿真等）统一使用此方案。

### 问题 3：PyInstaller 打包后双击闪退

**现象**：`pyinstaller --windowed` 打包的 .app，终端运行正常，但 Finder 双击一闪就没了。

**原因**：`gui_users.txt` 使用相对路径写入当前目录，双击 .app 时工作目录为 `/`，无写入权限导致 PermissionError 崩溃。

**解决**：将 `USER_FILE` 路径从 `"gui_users.txt"` 改为 `os.path.expanduser("~/.bjtu_canteen_users.txt")`，写入用户家目录。同时将 `dist/` `build/` `*.spec` 加入 `.gitignore`。

### 问题 4：集成测试中三种策略产生完全相同的分配

**现象**：`test_integration.py` 中距离权重 α=0.9 和排队权重 β=0.9 产生相同的食堂分配 `{0:9, 1:9, 2:12}`。

**原因**：初始状态下所有食堂排队人数为 0，两种策略都退化为纯距离选择。

**解决**：重构测试——手动构造两个位置不同的食堂 + 给 A 食堂加 10 个排队学生，验证距离优先选近的 A、排队优先选空的 B，确保选择器对不同权重做出不同决策。

### 问题 5：错峰对比各方案结果完全相同

**现象**：peak_shift.py 最初版本只改了全局 `spawn_rate`，不同 gap_time 的仿真结果几乎一样。

**原因**：`spawn_rate` 和 `student_count` 的简单变化无法模拟真实的建筑分批下课效果。

**解决**：完全重写为建筑分批注入模式——设置 engine 初始学生为 0、关闭持续生成，手动在指定 tick 分批 `Student` 注入到 engine。无错峰全部 tick 0 注入（峰值 66），错峰 30 分钟分 4 波注入（峰值 24），效果差异显著。

## 三、阶段总结

本项目从零开始，完成了北交大校园食堂就餐流量仿真系统的完整开发。作为组长，我负责核心引擎开发（models.py/engine.py/main.py）、系统集成、代码评审和部署验证。

**技术收获**：

1. **离散事件仿真**：掌握了 Tick-Driven 仿真引擎的设计模式，理解了有限状态机在仿真中的应用。
2. **Python 全栈开发**：从底层引擎到 GUI 到可视化到打包部署，完整走通了一条 Python 桌面软件开发链。
3. **跨平台兼容**：深入理解了 macOS/Windows/Linux 在字体、GUI 后端、文件路径上的差异和处理方式。
4. **集成测试**：学会了如何设计覆盖数据流链路的集成测试用例，以及单元测试 vs 集成测试的边界。

**项目成果**：

- 代码文件 17 个，总计约 5500 行
- 98 项测试全部通过（74 单元 + 24 集成）
- 跨平台验证（Windows/macOS/Linux）
- PyInstaller 打包验证（macOS .app）
- 三语支持（简体中文/繁体中文/English）
- 错峰对比定量结论：30 分钟错峰可降低排队峰值 64%

**不足与反思**：

Tkinter 作为 GUI 框架在 macOS 深色模式下存在先天缺陷，按钮、字体等受系统主题干预严重，产品级应用应考虑迁移至 PyQt 或 Electron。错峰对比目前仅通过分批注入近似模拟，未真正使用 class_schedules 中的时间表数据，后续可进一步精细化。
